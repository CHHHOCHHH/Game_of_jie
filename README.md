# 结 · 拍手游戏结系简化版

一个支持人机对战、AI 对战、以及离线训练策略表的拍手游戏。

规则细节见 `rules.md`，本 README 只讲怎么用。

---

## 一、文件结构

| 文件 | 作用 |
|---|---|
| `jie_core.py` | 核心引擎。定义技能表、结算规则、状态管理、资源封顶等。所有其他程序都依赖它。 |
| `jie_pi.pkl` | 训练好的**策略表**：每个状态 → 出招概率分布。 |
| `jie_V.pkl` | 训练好的**胜率表**：每个状态 → 博弈值 V（≈ 胜率 − 负率）。 |
| `jie_ai_vs_human.py` | 人机对战程序。P0 是人类，P1 是查表 AI。 |
| `test_ai.py` | AI 对战测试程序。让两种 AI 互相打 N 局，统计胜率和动作分布。 |
| `ai_king.py` | 最强 AI：查表后**按概率分布采样**。 |
| `ai_best.py` | 贪心 AI：查表后**永远选概率最大的招式**。 |
| `ai_random.py` | 随机 AI：在合法动作中均匀随机。 |
| `ai_defence.py` | 保守 AI：50% 防御、30% 结、20% 攻击。 |
| `ai_attack.py` | 激进 AI：有 2 费就出啸波×2，否则出结。 |
| `sample_result.txt` | `ai_king` 自我对战 1000 万局的统计结果。 |
| `check.py` | 检查 `jie_pi.pkl` / `jie_V.pkl` 是否合理的脚本。 |
| `training.py` | 训练脚本：重新生成 `jie_pi.pkl` / `jie_V.pkl`。**普通用户不需要运行。** |

## 二、快速开始：人机对战

```bash
python jie_ai_vs_human.py
```

你会作为 P0 与查表 AI（P1）对战。

### 界面说明

每轮会显示：

```
  P0: HP=2.0 点数=2 免单=1
  P1: HP=2.0 点数=2 免单=1
```

- **HP**：血量，保留 1 位小数，<= 0 死亡。
- **点数**：出招资源，上限 20。
- **免单**：出免单消耗，上限 2。

然后在用户输入招式后，显示双方各自视角下，最优出招式概率分布：

```
  [P0 视角] 状态=(4, 2, 1, 4, 2, 1)
    P0 应出的招式（策略表）:
      结            0.3880  █████████████████
      反弹          0.2992  ██████████████
      免单          0.1301  ██████
      ...
    → 最优: 结 (0.3880)
```

`状态` 是六元组 `(我方HP半值, 我方点数, 我方免单, 对方HP半值, 对方点数, 对方免单)`。

### 输入

```
P0 请输入 技能编号[ 发数]（例：1 2；-1 重置状态）:
```

- 输入 `技能编号`：例如 `9` = 结、`11` = 小防。
- 输入 `技能编号 发数`：例如 `1 2` = 啸波×2。
- 输入 `-1`：进入状态重置模式，可手动设置双方状态。

### 重置状态

输入 `-1` 后，程序会提示：

```
请输入六元组 (h0,pt0,tk0,h1,pt1,tk1)，如 (4,2,1,4,2,1):
```

输入格式：`(h0, pt0, tk0, h1, pt1, tk1)`。各字段：

| 字段 | 含义 | 范围 |
|---|---|---|
| h0 | P0 的 HP 半值 | 1~4（对应 0.5~2.0） |
| pt0 | P0 的点数 | 0~20 |
| tk0 | P0 的免单 | 0~2 |
| h1 / pt1 / tk1 | P1 的对应值 | 同上 |

例如 `(4, 5, 1, 2, 10, 2)` 表示 P0 满血 5 费 1 免单，P1 半血 10 费 2 免单。

## 三、AI 对战测试：`test_ai.py`

### 基本用法

```bash
python test_ai.py --p0 ai_king --p1 ai_random --games 10000 --seed 42
```

让 `ai_king` 作为 P0、`ai_random` 作为 P1，对战 10000 局，随机种子 42。

### 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--p0` | `ai_king` | P0 的 AI 模块名（不带 `.py`） |
| `--p1` | `ai_random` | P1 的 AI 模块名（不带 `.py`） |
| `--games` | 100000 | 对战总局数 |
| `--seed` | None | 随机种子。不指定则用系统时间 |
| `--report-every` | 10000 | 每多少局输出一次中间统计 |
| `--top-actions` | 0 | 最终动作统计输出前 N 条（0 = 全部） |

### 输出示例

```
随机种子: 42
P0 = ai_king, P1 = ai_random, 总 10000 局

[  1000 局] P0胜=   998 (99.80%)  平=     2 ( 0.20%)  P0负=     0 ( 0.00%)
[  2000 局] P0胜=  1995 (99.75%)  平=     5 ( 0.25%)  P0负=     0 ( 0.00%)
...

===== 最终结果（10000 局）=====
  P0 胜 (+1):     9978  (99.78%)
  平局  ( 0):       22  ( 0.22%)
  P0 负 (-1):        0  ( 0.00%)
  期望收益: +0.9978

===== 动作使用统计（共 10000 局）=====
  总动作次数: 141910  （平均每局 14.19 次）

  动作                 总计   每局平均
  --------------  --------   --------
  结                447838     44.78
  反弹              312151     31.22
  ...
```

`动作使用统计` 会列出每种招式（多重攻击的不同数量算作不同招式，如 `啸波×2` 和 `啸波×3`）被使用的总次数和平均每局次数。

## 四、可用的 AI

### `ai_king` — 最强 AI（查表 + 按概率采样）

从 `jie_pi.pkl` 读取状态对应的概率分布，**按概率随机采样**一个动作。

这是理论上最强的 AI：它的期望收益不低于任何对手，即“不可被利用”。

### `ai_best` — 贪心 AI（查表 + 取最大值）

从 `jie_pi.pkl` 读取概率分布，**永远选概率最大的招式**。

这比 `ai_king` 弱一点点，因为确定性策略可以被对手针对（如 `ai_attack` 能够开局 100% 干掉它）

### `ai_random` — 随机 AI

在合法动作中**均匀随机**。完全没有任何策略。

### `ai_defence` — 保守 AI

**50% 出防御、30% 出结、20% 出攻击**，各类内部均匀随机。

测试 `ai_king` 是否善于进攻。

### `ai_attack` — 激进 AI

**有 2 费就出啸波×2，否则出结**。开局必定啸波×2，如果对手不能防御就秒杀。

测试 `ai_king` 是否善于防守。

### 对战建议

```bash
# 智能 AI 对随机 AI
python test_ai.py --p0 ai_king --p1 ai_random

# 智能 AI 对激进 AI
python test_ai.py --p0 ai_king --p1 ai_attack

# 智能 AI 对保守 AI
python test_ai.py --p0 ai_king --p1 ai_defence --seed 42

# 智能 AI 自我对战（应该接近 50:50）
python test_ai.py --p0 ai_king --p1 ai_king --games 1000000 --seed 114

# 按分布采样 vs 取最大值
python test_ai.py --p0 ai_king --p1 ai_best
```

## 五、`sample_result.txt`

这是 `ai_king` 自我对战 1000 万局的完整输出。核心结果：

### 胜负分布

| 结果 | 数量 | 比例 |
|---|---|---|
| P0 胜 | 4,938,655 | 49.39% |
| 平局 | 123,353 | 1.23% |
| P0 负 | 4,937,992 | 49.38% |
| **期望收益** | — | **+0.0001** |

**几乎完美的对称**，验证了策略表是对称均衡。

### 平均每局 14.19 次动作

即约 7.1 轮（双方各出一招 = 1 轮）。

### Top 15 常用招式

| 招式 | 每局平均使用 |
|---|---:|
| 结 | 4.4784 |
| 反弹 | 3.1215 |
| 吸 | 1.8161 |
| 小防 | 0.9958 |
| 免单 | 0.8775 |
| 大拉 | 0.5619 |
| 啸波×2 | 0.4935 |
| 大防 | 0.3544 |
| 啸波×3 | 0.2830 |
| 地波 | 0.1901 |
| 摩擦 | 0.1813 |
| 致命 | 0.1480 |
| 拉 | 0.1295 |
| 派波 | 0.1103 |
| 大摩 | 0.1092 |

### 观察

- **结** 和 **反弹** 是绝对主力，合计占约 53%。
- **吸** 和 **小防** 是主要防御手段。
- **啸波×2 / ×3** 是最高频的攻击动作（前者可以秒掉结，后者可以秒掉任何单个大费攻击以获取平局）。
- **金龙波 / 世界末日 / 青龙波** 等昂贵技能几乎不出现（< 0.002/局），说明均衡里它们被更便宜的动作完全支配，也有可能是费用高的状态几乎不出现。

## 六、`check.py`（可选）

检查 `jie_pi.pkl` / `jie_V.pkl` 是否合理。

```bash
python check.py
```

输出包括：

- V 值范围、均值；
- 概率和是否都为 1；
- 对称性（V(s) 是否约等于 −V(镜像 s)）；
- 关键状态的 V 值和策略分布抽样。

如果指标正常，说明策略表和胜率表可用。

## 七、`training.py`（仅开发者）

**普通用户不需要运行这个程序。**

它通过值迭代 + 线性规划求解零和博弈的纳什均衡，生成 `jie_pi.pkl` 和 `jie_V.pkl`。

```bash
python training.py
```

一次完整训练约需 **15-20 分钟**。程序支持断点续训：中途 Ctrl+C 会保存 `checkpoint.pkl`，下次运行会询问是否继续。

参数（在 `training.py` 顶部常量区）：

| 常量 | 默认值 | 说明 |
|---|---|---|
| `TIME_PENALTY` | 3e-5 | 时间惩罚。值越小 V 越准，但收敛越慢 |
| `CONVERGENCE_TOL` | 1e-3 | 收敛阈值。delta < 此值即停止 |
| `NUM_WORKERS` | 8 | 并行进程数，按 CPU 核数设置 |
| `CHUNK_SIZE` | 1000 | 每个并行任务的状态数 |

如果修改了 `jie_core.py` 里的技能规则，**必须重新训练**，否则 `jie_pi.pkl` 会和实际规则不一致。

## 八、FAQ

### Q1: 运行 `jie_ai_vs_human.py` 报 `ModuleNotFoundError: No module named 'jie_core'`

确保所有 `.py` 文件和 `.pkl` 文件在**同一目录**下，并在该目录下运行命令。

### Q2: 报 `FileNotFoundError: jie_pi.pkl`

`jie_pi.pkl` 必须和程序在同一目录。如果丢失，运行 `python training.py` 重新生成，注意重新设置 `NUM_WORKERS` 为电脑的 CPU 核数。

### Q3: 我想自定义状态进行实验

在 `jie_ai_vs_human.py` 里输入 `-1`，然后输入六元组。

### Q4: 胜负结果为什么不是 50:50？

`ai_king` 自我对战时是 49.39% : 1.23% : 49.38%（1000 万局）。这是**近似均衡**的正常波动。加上平局拆分后，双方期望收益都是 +0.00005，差异远小于统计误差。

### Q5: 我能自己写一个 AI 吗？

可以。新建 `ai_myname.py`，定义：

```python
class AI:
    def __init__(self, seed=None):
        pass
    def get_movement(self, state):
        """
        state: (my_h, my_pt, my_tk, opp_h, opp_pt, opp_tk)
        返回 {(sid, n): probability} 的概率分布
        """
        return {(9, 1): 1.0}  # 示例：永远出结
```

然后用 `python test_ai.py --p0 ai_myname --p1 ai_king` 测试。具体可以参考其他已经写好的 AI，比如 `ai_random.py`。
